# 全链路延迟浮窗

浮窗的 `LAT` 从主机桌面或鼠标内容的实际更新时间开始，到副机 Windows
报告的系统显示事件结束。包含源内容更新后等待采集、GPU 复制、编码、
UDP 发送及接收、解码、渲染、Present 后的显示等待，不包含面板像素响应。

## 计算

接收器在每次 Present 前向当前用户共享内存写入 QPC、精确 UTC、源时间戳
及当帧校时参数。当前用户的受保护计划任务使用固定版本的 PresentMon
采集接收器 DXGI 事件，并匹配最近的逐帧标记。显示时间使用事件的 QPC
及 `msUntilDisplayed`，换算到源机器时间后减去原始桌面更新时间。

没有固定的显示延迟补偿，也不会用 Present 返回替代显示事件。后者只留作
诊断字段 `latency_endpoint=source_desktop_update_to_present_return`。
浮窗字段为 `hud_latency_endpoint=system_display`，实际显示测量字段为
`display_latency_endpoint=source_desktop_update_to_system_display`。

## 反馈与误差

事件统计可能约两秒后到达。`display_feedback_delay_ms` 记录观察器的滞后，
不是视频延迟；事件发生时间用于计算 LAT。最近 12 个有效源更新的均值用于
浮窗，另有滚动窗口 P50/P95。校时误差界限仍独立报告，不能忽略。

缓存纹理重复发送时保留原源时间戳，只计算同一源更新第一次实际显示。
否则静止桌面的“旧内容年龄”会被错误当成新的传输延迟。
未校时、校时过期、采样任务缺失或没有近期有效源事件时显示 `--`。
显示事件与最近有效样本的保留上限为五秒，跨 ETW 批次保留准确的旧事件统计，
超过上限立即失效。这个上限只影响统计可用期，不改变测得的链路延迟。

## 安装和生命周期

网络设置安装流程创建当前用户的交互式提升权限计划任务。
提升权限的执行文件及固定哈希的 PresentMon 放在受保护的 Program Files
目录，而不是从可由普通用户修改的便携目录运行。
任务仅跟踪当前用户、当前会话、当前软件启动的接收器 PID。
视频引擎在帧率切换时更换 PID，观察器随之切换。软件退出后关闭自己的
ETW 会话并退出，不停止其他工具的 ETW 会话。

目前双机验证使用管理员组中的交互式用户。标准账户由另一管理员安装的
权限与任务行为尚未完成验证。缺少任务时视频仍可运行，浮窗显示 `--`。

## 验证

`tests/validate_full_chain_hud.ps1` 使用软件控制接口和真实项目文档滚动，
在同一控制连接切换 165、240、165 档，检查实际接收器 PID、ETW 终点及
有效显示样本比例。它报告累计帧计数速率、延迟和校时界限，结束恢复 165。
配置目标、Present 提交速率、源内容更新次数和物理刷新次数是不同指标。
165 Hz 面板不能显示每秒 240 次完整物理刷新。
