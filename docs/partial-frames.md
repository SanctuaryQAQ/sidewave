# 只传输变化区域

“只传输变化区域（降低延迟）”默认关闭。开启后，桌面只有局部变化时，发送端只编码并发送
变化区域；全屏运动或变化区域过大时仍发送整帧。千兆网络上一帧 2K 4:4:4 约 450–500 KB，
传输本身约 4.6 ms，是全链路中最大的一段；局部帧直接缩短这一段，不降低画质。

## 工作方式

- **变化检测**：使用 Desktop Duplication 报告的 dirty / move 矩形，并加入发送端自绘鼠标指针的
  旧、新位置。没有变化元数据时发送整帧。
- **区域编码**：变化区域合并为一个矩形，向上取到尺寸档位
  （宽 256 / 512 / 768 / 1024 / 1536 / 2048 / 整屏宽，高 128–1024，每档 128），
  用对应尺寸的 PyroWave 编码器通过 `crop_rect` 从采集纹理 1:1 编码。编码器按需创建并缓存。
  档位面积超过整屏 75% 时发送整帧。
- **画质**：局部帧的字节预算按面积比例取自当前整帧预算，每像素码率与整帧相同。
- **协议**：局部帧使用 magic `0x50575259`，包头与整帧相同（28 字节）。第 0 个编解码包是
  8 字节区域描述 `{x, y, w, h}`（uint16），其后为编码数据。FEC、加密和分片不变。
- **接收端**：按区域尺寸缓存解码器（最多 24 个，超出淘汰最久未用），解码结果合成到常驻的整屏
  画布，再按原有缩放方式呈现。网络线程将局部帧按顺序排队（最多 16 帧），不像整帧那样只保留最新一帧；
  整帧到达时清空队列。
- **恢复**：每个局部帧同时重发前两帧的变化区域，单帧丢失在下一帧即补齐；另外每秒发送一次整帧，
  发送队列发生覆盖丢弃后的下一帧也强制为整帧。
- **兼容**：副机在握手中声明 `supportsPartialFrames`；主机只在对方支持时启用，旧版副机自动使用整帧。

## 实测（2026-10-11）

2560×1440、165 FPS、900 Mbps、4:4:4、明文 UDP、FEC、整形 900 Mbps，千兆有线经路由器。
开/关交替 8 轮、每轮 30 秒；延迟为接收端 ETW“源桌面更新 → 系统显示”P50，跨机时钟误差约 ±2 ms。

| 场景 | 每帧大小 | 每帧发送耗时 P50 | 线路占用 | 延迟 P50（关 → 开） |
| --- | ---: | ---: | ---: | ---: |
| 小窗口局部动画（约 3% 区域） | 474 → 32 KB | 5.08 → 0.39 ms | 691 → 71 Mbps | 12.91 → 9.33 ms |
| UFO 运动测试页（约 37% 区域） | 457 → 257 KB | 4.9 → 2.8 ms | 666 → 385 Mbps | 约 −1 至 −3.6 ms（两组） |
| 全屏运动 | 不变 | 不变 | 不变 | 不变（自动整帧） |

小窗口场景 6 组相邻开/关配对中 5 组开启更低；一轮开启期间副屏出现额外的大面积变化，
排除该轮后 P50 为 8.06 ms。P95 未见改善（15.35 / 15.49 ms），尾部延迟来自传输以外的环节。
局部帧开启时不完整帧由 20 降为 0（带宽降低后丢包减少）。接收端 CPU 解码与呈现耗时不变。
